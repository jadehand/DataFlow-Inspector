# 架构说明

## 目标

DataFlow Inspector 将 SQL、DDL、作业元数据和脱敏样例转化为可验证的数据资产、血缘、指标和影响报告。确定性结构由解析器生成，大模型仅负责基于证据解释。

```text
项目包
  │
  ├─ 安全校验与版本登记
  ├─ DDL / SQL 解析与标准化
  ├─ 样例剖析
  ▼
统一中间表示（IR）
  ├─ 资产目录
  ├─ 表级 / 字段级血缘
  ├─ 作业 DAG
  ├─ 指标与时间语义
  └─ 版本差异
          │
          ▼
      影响分析 / 证据式问答
```

## 组件

- **Web 前端**：项目导入、资产目录、图谱、作业 DAG、指标、影响分析和版本比较。
- **FastAPI 服务**：项目、导入、解析、血缘、指标和报告 API。
- **解析器**：SQLGlot 为基础，通过预处理和方言扩展兼容 GaussDB(DWS)。
- **PostgreSQL**：保存版本化元数据、邻接边、证据和人工覆盖；递归 CTE 完成影响传播。
- **样例剖析器**：只计算统计摘要，原始值与模型上下文隔离。
- **模型适配器**：可选外部或内网模型；停用后核心功能不受影响。

## 核心实体

`Project → ImportBatch → SourceFile → Statement` 保存输入版本；`Table → Column` 保存资产；`TableLineageEdge` 与 `ColumnLineageEdge` 保存来源、目标、转换表达式、文件位置和置信度；`Metric` 保存公式、粒度、过滤和时间语义；`ManualOverride` 独立保存人工确认。

## 解析策略

1. 无损保存原文件并计算哈希。
2. 用 manifest 示例变量替换宏，仅用于解析副本。
3. 将 DWS 专有存储参数等语法标准化。
4. 解析为与第三方 AST 解耦的 IR。
5. 单条语句失败时降级提取表依赖并降低置信度。
6. 重建资产、字段映射、指标和作业 DAG。

## 可信度模型

每个结论标记为：

- `parsed`：AST 直接证明；
- `inferred`：命名、使用方式或顺序规则推断；
- `ai_suggested`：模型建议；
- `confirmed`：人工确认。

界面不得把推断或 AI 建议显示为事实。所有血缘边应尽量定位到文件和语句。

## 安全边界

MVP 默认不连接生产数据库、不执行导入 SQL、不控制调度。ZIP 解包在隔离目录完成并防止路径穿越。删除导入版本只影响分析元数据。正式部署需限制上传大小、审计访问并为元数据库建立备份。

## 扩展点

后续可增加作业平台导出适配器、BI 元数据、Shell/Python 静态分析、OpenLineage 输出和 Neo4j。只有 PostgreSQL 递归查询成为瓶颈时才引入图数据库。
